# 統治ワークフロー

## リスクティア判定（AGENTS.md Section 5）

| ティア | 対象 | 手続き |
|---|---|---|
| **T1** | 文言・CSS・コメント・ドキュメントのみ | 即実行 → 一言報告 |
| **T2** | 新規コンポーネント、Props変更、状態管理更新 | 方針共有 → 実装 → ビルド/テストgreen → 報告 |
| **T3** | 統治構造、DBスキーマ、認証・権限、決済、破壊的操作 | SDR提案 → 人間承認 → 実行 → ADR記録 |

## 変更手順（AGENTS.md Section 6）

1. **調査**: 対象範囲・呼び出し元/先・影響するstateを確認。コードを変更しない
2. **計画**: T2以上は変更方針を一言でまとめる
3. **実装**: 計画に沿って変更。目的外の修正を混在させない
4. **検証**: 検証レベルに従い確認
5. **差分監査**: 意図した変更のみかを確認
6. **報告**: 何を・なぜ・どう検証したかを簡潔に伝える

## 検証レベル（AGENTS.md Section 7）

| レベル | 対象 | 必要な検証 |
|---|---|---|
| Lv.1 | 文言・CSS・コメントのみ | `npm run build` |
| Lv.2 | 単一ファイル内のstate/イベント | Lv.1 + ログ自己検証 → 人間に確認依頼 |
| Lv.3 | グローバルstate、I/O、複数ファイル | Lv.2 + ブラウザE2E確認 |
| Lv.4 | 認証・決済・本番リリース直前 | Lv.3 + 人間最終承認 |

## 完了処理

1. `npm run done` を実行し、出力された完了コード（GSEAL）を報告に添える
2. `git status` で意図しないファイルが含まれていないか確認
3. T3の場合は `governance/ADR/` に記録

## T3 SDRフォーマット

```
[State]: 現在の状態・コンテキスト
[Decision]: 提案する判断
[Reason]: その理由
[Risk]: リスクとその軽減策
[Unknown]: 不明点
```
