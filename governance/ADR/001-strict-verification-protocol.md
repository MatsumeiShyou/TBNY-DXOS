# ADR 001: Strict Verification Protocol の導入

## Status
Accepted

## Date
2026-08-09

## Context
ユーザーより `/learn` コマンドを通じて、「実装後は必ずテストと実装内容の動作証明を行い、すべて合格させてから報告すること。合格しない場合は修正計画を報告し承認を求めること」という強い要望・制約の指定があった。
これは既存の `[C-E-V]` プロトコルによる成功証明の提示をさらに厳格化し、AIエージェントがエラー発生時に独自の推測で勝手に修正ループ（応急処置）に入ってしまうことを防ぐためのフェーズ分割（動作証明 → 失敗時承認プロンプト）の義務化である。

## Decision
最高憲法である `AGENTS.md` の「2. B群：認知と推論による遵守 (Cognitive Compliance)」に、新ルール `[Strict Verification Protocol]` を追加した。

```markdown
- **[Strict Verification Protocol]**: 実装後は必ずテストと実装内容の動作証明（ビルド、Lint、型チェック等）を実行し、すべて合格させてから報告せよ。合格しない（エラーが発生した）場合は、その場で勝手な応急処置を試みるのではなく、必ず修正計画を報告しユーザーの承認を求めてから修正を実行せよ。
```

## Consequences
- 実装・修正タスク完了後、AIは必ず `npm run build` や `npm run type-check` (またはそれに準ずるテスト・Lint) などを実行し、その物理的成功ログを取得してから報告を完了しなければならない。
- エラーが発生した場合、AIは自律的な修正（推測による応急処置）を即座に実行するのではなく、エラー原因の分析結果と「次に行うべき修正計画」を提示し、ユーザーからの明示的な「Proceed (y)」を待つ義務を負う。これにより、意図しない破壊的変更のループやデッドロックが防止される。
