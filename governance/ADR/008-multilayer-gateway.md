# ADR-008: 多層ゲートウェイパターンの導入（統合的GRCインフラ）

## 1. Context（背景）
現在の統治構造（`AGENTS.md` ベース）は強力な行動規範（最高憲法）として機能しているが、AIエージェントの推論能力に依存する「確率的」な防衛層しか持たず、ハルシネーションやエラーによる逸脱リスク（ABS-1、ABS-2違反など）を物理的に防ぐ仕組みが欠落していた。
また、エラー発生時にエージェントが自律的に気付けないことで、開発のアジリティ（速度）が損なわれるケースも存在した。

## 2. Decision（決定事項）
システムの統治インフラとして、「プロンプト依存（確率論）」と「フック強制（決定論）」を並行稼働させる**多層ゲートウェイパターン（Multilayer Gateway Pattern）**を導入する。

具体的には、Antigravity基盤のツールフック機能を活用し、以下の3層のゲートを物理的に強制する：
1. **第一層（PreToolUse）**: `write-safety-check.js` 等を用い、シークレットや破壊的コードの書き込みをミリ秒単位で事前ブロックする。
2. **第二層（PostToolUse）**: `post-write-check.js` を用い、`eslint --fix` を同期実行して静的解析エラーを「追加コンテキスト」としてエージェントに自律修復（自己修復ループ）させる。
3. **第三層（Closure Gate）**: `done.js` と `closure_gate.js` を連携し、完了条件（README更新、GSEAL記録等）を満たさない限りタスクを完了させない。

## 3. Reason（理由）
- 最新の「複雑な統治構造における安全な移行・改善フレームワーク」に基づき、エージェントの行動変容（アジリティ）を維持しつつ、致命的なエラーをシステム層で決定論的にブロック（フェイルセーフ）するため。
- 介入ゾーン（Green/Yellow/Orange）を定義することで、誤検知によるデッドロック発生時でも `hooks.json` からエントリを外すだけで即座にロールバック（旧体制へ復帰）可能な安全弁を確保できるため。

## 4. Consequences（結果・影響）
- **ポジティブ**: シークレット漏洩やデータベース破壊（ABS-1, 2）のリスクが極小化される。構文エラーがその場で自律修復されるため、後続フェーズでの手戻りが減る。
- **ネガティブ**: フックの設定ミス（誤検知）が発生した場合、エージェントが同一タスク内で足踏みする可能性がある（イエローゾーン）。その場合は原因分析とロールバック手順に従う。
- **今後の展望**: Phase 5（将来課題）として、異種データソース（Supabase）統合時に、PreToolUse層にデータ正規化フックを拡張する。
