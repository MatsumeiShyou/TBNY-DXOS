# ADR-003: 並行編集時の衝突ポリシー（悲観的ロックベースの可視化）

## 状態 (State)
- 配車センターにおいて、複数の配車オペレーターが同時に同一の配車画面（案件リスト、車両スケジュール）を操作するユースケースが存在する。
- 現状はローカルストレージや手動での同期に頼っており、2人が同じJobを別々の車両に同時にドラッグした際の動作が未定義であり、実務上の混乱（配車の重複や消失）を招くリスクがある。

## 決定事項 (Decision)
- 配車操作の競合解決手段として、「Last-Write-Wins (後勝ち)」や「サーバー側での確定的な自動マージ」は採用せず、**「ドラッグ中（編集中）のJobに対する悲観的ソフトロックの適用とUI上での可視化」** を正式なポリシーとする。
- 誰かがJobをドラッグした瞬間にそのJobを「編集中」としてロックし、他のオペレーターの画面では該当Jobを操作不能（グレーアウト＋編集者の明示など）にする。

## 理由 (Reason)
- **実務感覚との整合性**: 配車・シフト管理という業務上、意図しない自動マージや後勝ちによる上書きは、現場のトラックの配車ミスという重大な物理的インシデントに直結する。
- **実装コストの適正化**: 複雑なCRDT（Conflict-free Replicated Data Type）やマージロジックを自作するよりも、Supabase Presence や Realtime broadcast を利用したロック・可視化の方が実装がシンプルであり、ROI（投資対効果）が高い。

## リスク (Risk)
- ネットワークの瞬断等でロック解除のイベントがロストした場合、Jobが永続的にロックされたままになる「ゾンビロック問題」が発生しうる。
- 対策として、一定時間（例: 30秒〜1分）経過後にロックを自動解除するTTL（Time To Live）機構、または強制解除ボタン（管理者権限）の導入が必要となる。

## 今後の展望 (Future Work)
- 本ADRで定めたポリシーに基づき、Supabase Realtime API を活用したUI側のソフトロック実装を次期フェーズで実施する。
