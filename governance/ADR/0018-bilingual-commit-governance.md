# ADR 0018: バイリンガル・コンベンショナル・コミットの統治（Bilingual Commit Governance）

## 1. 背景 (Context)
*   ユーザーのグローバルルール（B-3）により「技術的必然性がない限り日本語を使用する」ことが義務付けられている。
*   しかし、コミットメッセージを無条件にすべて日本語化すると、`semantic-release` 等のグローバルなOSSツール群との互換性が失われ、CI/CDパイプラインにおける変更履歴生成（Changelog）が機能しなくなる。
*   さらに、AIエージェントに自律実行を許可した場合、エージェントが英語のコミットメッセージを生成してしまい、後からの監査においてコンテキスト（文脈）の理解度が著しく低下するインシデント（B-3違反）が常態化するリスクがあった。

## 2. 決定 (Decision)
*   **バイリンガル・コンベンショナル・コミットの強制**: 
    コミットメッセージの先頭には英語による Conventional Commits のタグ（`feat:`, `fix:`, `docs:` 等）を使用し、その後に必ず「日本語（ひらがな・カタカナ・漢字）」を含める構造を必須とする。
*   **構造的検証ゲートの追加**:
    `closure_gate.js` 内に正規表現バリデータ（`/[\u3040-\u30ff\u3400-\u4dbf\u4e00-\u9fff\uf900-\ufaff]/`）を導入し、日本語が含まれないコミットを物理的に遮断（process.exit）する。
*   **文字コード監査の拡張**:
    `guardian_charset.js` の監査対象ファイルに `.agent/session/evidence_draft.md` および `walkthrough.md` を追加し、動的証跡生成時の文字化け（CP932/Shift-JIS 汚染）をブロックする。

## 3. 影響 (Consequences)
*   **Positive**:
    *   OSSエコシステム（英語ベースのツールチェイン）との完全な互換性を維持できる。
    *   AIエージェントによる英語コミットのすり抜けを物理的に防ぎ、恒久的な監査能力（人間およびAIによるコンテキスト理解度）を最大化できる。
    *   文字化けリスクが低減し、Windows環境下でも安定したログ保存が可能になる。
*   **Negative**:
    *   メッセージに意図的に日本語を含める必要があるため、完全な英語のみの開発フローには適用できなくなる（ただし本プロジェクトの性質上これは許容される）。
